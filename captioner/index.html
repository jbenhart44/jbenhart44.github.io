Captioner

A visible, subject-identifying caption under every picture in a PowerPoint deck — plus optional WCAG alt-text (the OOXML descr field) for images that have none. Opt-in, preserves existing alt-text, with an auditable trail. It fills a required field; it does not certify WCAG conformance, and authored wording is not independently verified — review it before you rely on it.

What it does

For every picture in a .pptx deck, captioner inserts a short (5–15 word) italic caption directly below the image. The caption identifies what the picture is — so sighted students know at a glance, and so a reviewer has a written record of every visual on every slide.

Captioner can also (with --write-descr, opt-in) author the OOXML descr attribute — the alt-text a screen reader announces — for pictures that have none, while preserving any alt-text a deck already carries and marking decorative images as decorative. These are two independent layers: the visible caption on the slide canvas, and the invisible alt-text in the file. Writing that attribute fills a required field; it does not by itself certify WCAG 2.1 conformance, and the authored wording is not independently verified — review it before you rely on it.

Each run is non-destructive (the source .pptx is preserved untouched), idempotent (re-runs replace prior captions cleanly), and produces a per-deck audit CSV that records the exact action taken on every shape it encountered.

Not limited to engineering — works across disciplines

Captioner was first built for engineering course decks, but it has no built-in field taxonomy: it adapts to whatever subject you supply through a one-line --context prompt at the start of a run, so the captions and alt-text it writes draw on the right vocabulary for the subject at hand — for example --context "Biology 101 — cell mitosis", --context "Art History — Baroque painting", or --context "Constitutional Law — the commerce clause".

Those field names are only examples of the kind of context you can pass — not validated test cases, and not a claim the tool has been benchmarked in those fields. Caption and alt-text quality depend on the images and the context you provide; review the output before you rely on it.

What captioner reads and writes

Captioner reads the .pptx file(s) you point it at and the images embedded inside them. The captions and alt-text are generated by Claude Code’s vision, which runs on Anthropic’s API — so the picture content of your slides is sent to Anthropic for processing, the same as any other Claude Code request. (Captioner’s own scripts add no separate network call or third-party service.) If your decks contain restricted material (for example FERPA-covered student work), review Anthropic’s data-use terms first. Your original .pptx is never modified. Each run writes into a working directory you choose:

  • a new captioned copy at <work_dir>/captioned_decks/<deck>_captioned.pptx
  • a per-deck audit trail at <work_dir>/audit/<deck>_audit.csv (plus <deck>_descr_audit.csv when you pass --write-descr)
  • with the default QC pass, flag-only quality-check files at <work_dir>/qc/<deck>_spellcheck.csv and <work_dir>/qc/<deck>_qc.csv

The installer itself touches exactly one path on your system, ~/.claude/skills/captioner (or $CLAUDE_SKILLS_DIR/captioner), and announces what it is about to do there before it acts (see Install).

Capabilities

Every capability below is concrete and enforced by an automated verification gate on each run.

  1. Subject-identifying captions. Each picture gets a short (5–15 word) category-prefixed caption — Photo:, Illustration:, Diagram:, Chart:, Screenshot:, Logo:, Map:, or Icon: — chosen from visual context. Pure subject identification: no descriptive prose, no “image of…” filler.
  2. WCAG alt-text authoring (opt-in --write-descr). Captioner can write the OOXML descr attribute — the alt-text a screen reader reads — for pictures that have none. It is preserve-by-default: any existing alt-text is left untouched (never overwritten), and decorative images get PowerPoint’s native decorative marking instead of a description, so screen readers skip them. --descr-only writes alt-text and adds no visible caption. This fills a required field for images that lacked one; it does not certify WCAG 2.1 conformance, and the authored wording is not independently verified — review it before relying on it.
  3. Domain-context prompt. Because good alt-text is often subject-specific, captioner asks for a one-line course/topic context at the start of a run (e.g. “Biology 101 — cell mitosis and the cell cycle”) and uses it to make both the visible captions and the authored alt-text domain-accurate. Scripted runs are unaffected.
  4. Vision reads in-image text. When a picture contains typography rendered as part of the image (a warning sign, a screenshot of code, an annotated chart), the caption reproduces the relevant text — not just shapes and colors.
  5. Legible on any background. Each caption sits in a small white card with a light-gray border, so it stays readable on dark section dividers and dark-themed slides where black text would vanish.
  6. Text-aware 2D placement — never covers text. Every text-bearing element (title, subtitle, body, and plain text boxes / auto-shapes) is treated as an obstacle the caption routes around in both dimensions. The occupied text region is measured font- and line-break-aware, so a multi-line or large-font title is correctly avoided rather than under-estimated as a single line.
  7. Captions stay with their picture. Placement prefers directly below the picture; when space is tight it uses a small, unobtrusive band at the picture’s own bottom edge (a thin strip overlapping a sliver of image) rather than letting the caption drift up into the title/body text. Only if even that would cover text is the picture left uncaptioned and flagged for review.
  8. Repeated-background suppression. A full-slide background image that repeats across many slides is detected as template chrome: it is neither captioned (no clutter on every slide) nor treated as a placement obstacle — so the real pictures on those slides still get captioned instead of being blocked by the background.
  9. SmartArt per-icon captioning, no vision pass. PowerPoint stock Icons embedded in a SmartArt store their human-readable name in the SVG id attribute. Captioner reads each name deterministically from the XML and places a short caption directly under the icon — no model call, no variability. Caption size scales to the icon: small icons get small captions (font and box shrink to match) so the caption card never dwarfs the icon it labels.
  10. Decorative & text-only-SmartArt triage. Repeating logos, bullet markers, and slide-master decoration are recorded as [decorative] with no visible caption. SmartArts whose only content is text labels are intentionally skipped — the text already lives in the slide’s accessible text layer.
  11. No overlaps, ever. Two captions never touch, a caption never lands inside a different picture, and nothing intrudes the footer-clearance band (configurable). When no clean position exists, the row is recorded as flagged-no-slot — never forced into a bad spot.
  12. Six-pattern placement gate, plus alt-text coverage. Every run is checked by an independent verifier for six placement defect classes in 2D coordinates — text-overlap, footer intrusion, caption-inside-picture, caption-on-caption, caption text overflow, and a band caption burying a small/structural picture — plus (with --descr) an alt-text coverage gate that confirms every picture is either given a descr value or marked decorative. It exits non-zero on any defect; intentional skips are recognized as known-skips, not failures.
  13. Audit CSV trail & idempotent re-runs. Every action the tool takes on every shape is logged to a per-deck CSV alongside the output. Caption shapes carry a content-hash name, so re-runs (--update-existing) replace prior captions cleanly — no duplicates accumulate — and hand-edited captions are preserved rather than clobbered.
  14. Configurable & non-destructive. The source .pptx is preserved untouched. A free-text deck context can bias vocabulary; toggles include --no-smartart, --bg-repeat-threshold, and a default-on, whitelist-aware spell-check / date QC pass (--quick / --no-spellcheck / --no-dateqc) that never silently “corrects” a real proper noun.

Scope note. Captioner writes two independent things: a visible caption on the slide for sighted readers, and — with --write-descr — the programmatically determinable OOXML descr attribute consumed by screen readers (WCAG 2.1 Success Criterion 1.1.1’s text alternative), for images that lack one.

Populating that attribute is necessary but not sufficient for compliance: captioner does not certify WCAG 2.1 conformance (it authors one attribute for a subset of images and does not touch charts, embedded objects, or non-picture shapes), and the correctness of the authored wording is not independently verified — a human should review it. Best positioned as an accessibility head-start with an auditable trail, to pair with a full alt-text review rather than replace it.

What captioner does NOT do

  • Write alt-text by default, or overwrite existing alt-text — the OOXML descr field is only authored when you pass --write-descr, and any alt-text a deck already has is preserved untouched.
  • Certify WCAG conformance, or verify that the alt-text it authors is correct — it populates the field for images that lacked one; a human should review the wording.
  • Read off chart values — captions identify “this is a chart of X”, not what its data says.
  • Modify embedded charts, the slide master, or any non-Picture shape.
  • Process .ppt legacy format (python-pptx supports .pptx only).

Reliability

What backs each run is the verification gate, not a track record: every deck is checked by an independent verifier for six placement defect classes (text-overlap, footer intrusion, caption-inside-picture, caption-on-caption, text overflow, and a band caption burying a small picture) in 2D coordinates, plus — with --descr — an alt-text coverage gate. The verifier exits non-zero on any defect, so a caption over text, off-slide, inside another picture, or overlapping another caption cannot ship silently. It handles a wide range of layouts: title slides, dense bulleted content, photo grids, SmartArt icon strips, full-bleed backgrounds, and dark section dividers.

Runs are non-destructive — the original .pptx is preserved untouched — and every action is logged in a per-deck audit CSV for review and editing before sharing.

Install

Before you start: the steps below are typed into your computer’s command-line Terminal (on macOS, open Terminal from Spotlight; on Windows, use the WSL or Git Bash shell). If working at a terminal is unfamiliar, this is a good point to hand the link to your IT or instructional-design team, who can run these steps for you.

Prerequisite: Claude Code must be installed — it provides the image-reading (vision) capability the workflow depends on. Captioner runs inside Claude Code, not as a standalone program. You also need Python 3.9+ with git available; the Python packages (python-pptx, lxml, Pillow, pyspellchecker) install in the steps below from requirements.txt.

  1. Clone the repository (pinned to v0.3.0).
    git clone https://github.com/jbenhart44/captioner.git
cd captioner
git checkout v0.3.0
  2. Install Python dependencies.
    pip install -r requirements.txt
  3. Run the installer.
    bash install.sh
    This symlinks captioner into your Claude Code skills directory (~/.claude/skills/captioner). It touches only that one path, prints exactly what it is about to remove before replacing an existing install, and checks all four Python dependencies for you.
  4. Restart Claude Code, then run /captioner <path-to-.pptx-or-folder> to caption a deck. To also write alt-text, add --write-descr.
  5. Check the alt-text you wrote. Alt-text is invisible in the normal PowerPoint view. To see it, open the deck in PowerPoint, right-click a picture → View Alt Text, or run Review → Check Accessibility. Confirm the wording is accurate before you rely on it.

Updating to a new version

cd captioner
git fetch --tags
git checkout <new-version-tag>      # e.g. v0.3.0 — replace with the version you want
pip install -r requirements.txt     # re-run: cheap, and a version bump can add a dependency
bash install.sh                     # safe to re-run — a same-target relink just prints "nothing to do"

Then restart Claude Code. Stay on a tagged release — do not run git checkout main or git pull, which can pull unreleased work instead of a stable version.
