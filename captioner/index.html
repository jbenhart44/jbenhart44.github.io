Captioner

Brief, subject-identifying captions under every picture in a PowerPoint deck — with an auditable trail.

What it does

For every picture in a .pptx deck, captioner inserts a short (5–15 word) italic caption directly below the image. The caption identifies what the picture is — so sighted students know at a glance, and so a reviewer has a written record of every visual on every slide.

Each run is non-destructive (the source .pptx is preserved untouched), idempotent (re-runs replace prior captions cleanly), and produces a per-deck audit CSV that records the exact action taken on every shape it encountered.

Capabilities

The capabilities below are concrete and verified on a production run across three graduate engineering courses.

  1. Subject-identifying photo captions. Each photograph gets a brief category-prefixed caption (Photo: colored pencils in holder beside stacked books and chalkboard.). Pure subject identification, no descriptive prose, no “image of…” filler.
  2. Category-aware prefixes. The skill distinguishes Photo:, Illustration:, Diagram:, Chart:, Screenshot:, Logo:, Map:, and Icon: from visual context — without course-specific tuning.
  3. Vision reads in-image text. When a picture contains typography rendered as part of the image (a warning sign, a screenshot of code, an annotated chart), the caption reproduces the relevant text — not just shapes and colors.
  4. White-card background fill for dark slides. Captions sit in a small white card with a light-gray border, so they remain legible on any slide background — including dark section dividers and dark-themed slides where black text would be invisible.
  5. Three positioning fallbacks. Captioner prefers placing the caption directly below the picture. When room is tight, it falls back to above the picture; when neither fits, it lands at the slide bottom. The audit CSV records exactly which fallback fired.
  6. SmartArt per-icon captioning, no vision pass needed. PowerPoint stock Icons embedded in a SmartArt store their human-readable name in the SVG id attribute (Icons_VideoCamera). Captioner extracts each icon’s name deterministically from the XML and places a short caption (video camera) directly under it — no LLM call, no variability.
  7. Decorative-image triage. Repeating logos, bullet markers, and slide-master decoration are flagged as [decorative] and recorded in the audit; no visible caption is added.
  8. Text-only SmartArt skip. SmartArts whose only content is text labels are intentionally not captioned — the text is already in the slide’s accessible text layer, and a combined caption would be redundant clutter.
  9. Deck-level context. A free-text context string (e.g., a course title or lecture topic) can be passed at run time to bias caption generation toward course-appropriate vocabulary.
  10. Audit CSV trail. Every action — added, fallback-above, fallback-bottom, skipped-decorative, skipped-no-caption, added-smartart-icon, skipped-smartart-text-only — is logged in a CSV alongside the captioned output. Faculty can review and edit captions before sharing, and re-runs with --update-existing regenerate the deck cleanly.
  11. Idempotent re-runs. Captioner shapes are named with a content-hash suffix so they can be recognized and replaced on subsequent runs. No duplicate captions accumulate across iterations.

Scope note. Captioner produces visible compliance-style captions for sighted readers. It does not, on its own, satisfy WCAG 2.1 Success Criterion 1.1.1 — that criterion requires a programmatically determinable text alternative (the OOXML descr attribute consumed by screen readers), which captioner does not write today.

Captioner is best positioned as a pedagogical-clarity layer with an auditable trail, designed to pair with full WCAG alt-text remediation. A one-flag --descr extension is on the roadmap.

What captioner does NOT do

  • Write the OOXML descr alt-text field (the WCAG-canonical attribute consumed by screen readers).
  • Read off chart values — captions identify “this is a chart of X”, not what its data says.
  • Modify embedded charts, the slide master, or any non-Picture shape.
  • Process .ppt legacy format (python-pptx supports .pptx only).

Extending captioner

The eleven capabilities above are the ones already shipped. The tool is designed to be extensible — every capability so far was added in response to a concrete production-run observation, not pre-imagined. Examples of capabilities that could be added if useful:

  • A --descr mode that writes the visible caption text into the OOXML alt-text field as well, closing the WCAG 2.1 SC 1.1.1 gap in the same pass.
  • Per-course context tuning files (vocabulary biases for quality engineering, finance, compliance, etc.).
  • Caption styling presets (font, color, position, card shape) configurable per course.
  • Alternative caption languages for international student audiences.
  • Chart-value summarization (reading off the actual data points, where helpful).
  • Image-category opt-in / opt-out lists (e.g., always caption photos, never caption diagrams) at the deck level.
  • Native PowerPoint Add-in packaging so the workflow runs from inside PowerPoint without command-line access.
  • Batch summaries — a single one-page PDF per course summarizing what changed across all decks.

If any of these — or something not listed — would be useful for a specific course, deck, or workflow, the addition is generally a small change because the underlying pipeline (extract → caption → audit → apply → verify) is modular.
